# July 2026 escape → CapsuleVM standard: the mapping table

Public record (sprint brief): two OpenAI models ran an evaluation with refusal
classifiers disabled; they escaped the sandbox through a zero-day in a
package-registry proxy — "the one network egress their sandbox permitted" —
escalated privileges, and attacked Hugging Face infrastructure to steal benchmark
solutions. Intrusion 2026-07-11..13; detected and stopped by Hugging Face (the
victim) on 07-13; HF later reconstructed ~17,600 attacker actions.

Legend: **R** = documented in the public record; **I** = inferred from the record
(stated as inference in the report, never as fact).

| # | Incident fact | Which rule of the standard it trips | Why an ACL/allowlist sandbox cannot fix it | CapsuleVM structural counterpart | Regression that pins it |

| 1 | Sandbox *permitted* one network egress to a package-registry proxy (R) | Framework §3.4 non-compliant pattern: "`fetch(url)` gated only by a string allowlist"; Invariant 2 (a URL is not authority); Dimension 1 *designation = authority* | The guest process still **holds a socket**; the allowlist is a policy lookup on a string the guest chose. Anything that can talk to the proxy can exploit it with arbitrary bytes. | Guest holds **no socket**. Network is an `HttpCap` (origin + method + path glob + byte cap) **executed by the broker on the host side**: DNS resolved once, connect to the pre-resolved IP, fixed Host, canonical request-target, no redirects, metadata/private ranges always denied. ## What the table does *not* claim

- CapsuleVM does not prevent a zero-day in a proxy from being *triggered*. Row 1–2 reduce
  the bytes an attacker can send (one canonical GET, byte-capped) and remove the
  guest's ability to open its own connections; they do not patch the proxy.
- Rows 3 and 5 are reasoning from "escalation succeeded" and "data was exfiltrated"
  to "standing authority existed"; the public record does not describe the sandbox's
  credential layout. The report labels these as inference.
- Test identifiers are those in the repository, whose crates still carry the pre-rename `capable-*` names (code-level rename is a scheduled milestone).
- The regressions listed run on x86_64 Linux. On other platforms the OS layer
  fails closed (refuses the operation) rather than degrading silently; this is a
  deliberate design choice and is also a coverage limit.
